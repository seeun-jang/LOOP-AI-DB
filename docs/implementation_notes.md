# 기존 자료 확인 및 설계 조정

확인한 저장소: `seeun-jang/LOOP-AI-DB`, 기준 커밋 `b97a689`. 실제 clone 후 모든 파일을 확인했다. 기존 backend/main.py, SQL 3종, HTML/CSS/SVG, Markdown 설계 문서, drawio, README, requirements, .gitignore는 각각 2바이트의 빈 파일이었다. 작성된 원본은 루트의 설계 보고서 PDF와 관계도 PNG 2종이었다. 연결된 대화에서도 추가 HTML/CSS/SVG 원본은 제공되지 않았으므로 기존 코드를 재사용했다는 주장을 하지 않는다. 빈 파일 경로를 유지해 구현했고 PDF·PNG 원본은 보존했다.

| 설계 쟁점 | 확정한 구현 | 이유 |
|---|---|---|
| 대화의 아이디 길이 30·제목 150 vs PDF의 50·200 | user_id VARCHAR(50), title VARCHAR(200) | 실제 저장소 보고서의 기준에 통일, API도 같은 길이 |
| 한글 속성명 vs 코드 필드명 | 영문 snake_case, 화면·명세는 한글 대응 | SQL·Python·웹에서 같은 이름 사용 |
| 시작·작성·제출 시각 TIMESTAMP | TIMESTAMPTZ, 화면은 Asia/Seoul | DB 시간대 차이로 기록 순서·표시가 어긋나지 않게 함 |
| 진행상태 허용값 | in_progress/completed/stopped | 화면에는 진행중/완료/중단, DB와 입력 모델 CHECK 일치 |
| 작성주체 | user/assistant | Gemini 전송 시 assistant만 model로 변환 |
| 회원↔주제 선 해석 | 회원→세션, 주제→세션 | 직접 관계를 추가하지 않고 7 FK 유지 |
| 세션 삭제의 범위 | 메시지·문제·풀이 CASCADE | 고아 데이터 방지, 한 트랜잭션 |
| 주제 관리 권한 | 공용 seed/직접 SQL로 관리 | 일반 회원이 다른 회원의 공용 주제를 바꾸지 않음 |
| A/B 결과 0~2개 가능 vs 비교 완료 | DB 최대 2개, API 성공 시 정확히 2개 | 한쪽 AI 실패 시 아무 실험도 저장하지 않음 |
| 피드백 저장 시점 | 동기 생성 후 제출·결과 함께 저장 | 이번 구현은 실패 시 제출도 롤백, 채점 대기 큐는 미구현 |
| 정답률 집계 | 정답 제출 / 모든 제출, 반복 시도 포함 | 보고서 기준. 채점 대기는 분모에 포함·별도 개수 반환 |
| 보안 비밀키 | 서버 .env만 사용, setup에서 난수 생성 | 프런트엔드·Git·문서에 실제 키를 넣지 않음 |

추가한 `UNIQUE(topics.name)`, 공백 문자열 CHECK, 아이디 형식 CHECK, FK 경로 인덱스는 무결성과 조회 효율을 위한 보완이다. 이메일은 필수 형식만 검사하고 유일성은 요구하지 않는다. 회원 이름은 비워둘 수 없다. 토큰 검증과 모든 하위 데이터의 소유권 검사를 FK와 별도로 수행한다.

생성 중 중간 레코드를 노출하는 대신 외부 AI 호출·응답 검증 후 기록을 저장한다. 대화/풀이/문제 생성 중에는 세션 행 잠금으로 같은 세션의 쓰기를 직렬화한다. 대화 내역의 원본 순서는 메시지 번호, 풀이 순서는 풀이 번호를 사용한다.
